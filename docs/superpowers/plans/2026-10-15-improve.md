# Improve Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Roadmap sub-project 4: one Improve pipeline (Backlog · In progress · Shipped · Signals) built on the Claude
board, replacing the separate Change requests, Issues, Quality signals and Claude Code pages.

**Architecture:** Pure rules in a new `app/improve.js` (stage, promotion, ranking actions, one idempotent
`reconcile`). `server.js` keeps the board store, adds `/api/improve/*` routes and calls `reconcile` at the few moments
state can change. A new client file `app/public/improve.js` renders four registry pages with sub-project 1's
components; old page ids become aliases.

**Tech Stack:** Node 22.13+ built-ins, `node:sqlite` through `app/storage.js`, vanilla JS/CSS, `node --test`,
Playwright, vendored axe-core.

**Spec:** `docs/superpowers/specs/2026-10-15-improve-design.md` (and the roadmap
`docs/superpowers/specs/2026-10-15-localai-evolution-design.md`).

  `LocalAIUI` from `components.js`).
- Element ids checked by `deploy/Test-LocalAI-Candidate.ps1` stay in `index.html`; tests move with pages (rule 3).
- Copy (exact): stage tabs `Backlog`, `In progress`, `Shipped`, `Signals`; actions `Start`, `Hand to Claude`,

  `+ New idea`, `Add to backlog`, `Start now`; badges `Handed to Claude`, `Needs a look`; note `Resolved on its own`.

## Review Focus

1. **A Claude session re-reports a finding that is a backlog item** → its votes, notes, `source`, `changeId`,
   `handedToClaude` and `shipped` survive (today's normalizer drops unknown fields). Test in Task 2.
2. **A Signal keeps recurring after it was promoted, or after its item was rejected** → no second item, and a rejected
   item stays rejected. Test in Task 1.
3. **A change linked to an item is deleted or missing from the store** → the item falls back to Backlog, no crash.
   Test in Task 1.
4. **Two scans finish close together (or reconcile runs twice)** → still one item per Signal and per change. Test in Task 2.
5. **An idea of only whitespace, or 20,000 characters** → 400 for empty; long text is kept in `summary` (2000 chars,
   the normalizer's limit) with a 120-char title. Test in Task 3.

### Task 1: Improve rules (pure)

**Files:**
- Create: `app/improve.js`
- Test: `tests/improve.test.cjs`

**Interfaces:**
- Produces (CommonJS exports):
  - `LIVE_CHANGE = ['planned','patch_failed','validation_failed','staged','awaiting_approval','approved','apply_requested']`
  - `stageOf(item, changesById) → 'backlog'|'inProgress'|'shipped'|'setAside'` (spec "Data and stages" table, first match wins)
  - `shouldPromote(signal) → boolean`: `status==='open' && (severity==='high' || occurrences>=3)`
  - `signalItemId(signalId) → 'signal-'+signalId`
  - `promoteSignal(signal, at) → finding` (`source:'signal'`, `signalId`, `status:'proposed'`, severity, `title` = signal name ≤240, `summary` = detail ≤2000)
  - `ideaItem(text, at) → finding|null` (`source:'idea'`, `status:'approved'`, id `idea-<at ms>-<4 hex>`, title = first line ≤120, summary ≤2000; `null` when text is blank)
  - `moveToTopBoost(item, openItems, scoreOf) → number` (new `priorityBoost` making `scoreOf(item)` = max open score + 1)
  - `handToClaude(item, at) → patch` (`status:'approved'`, `handedToClaude:true`, `handedAt`, `priorityBoost: +30`, `decisionNote` "Handed to Claude", appended after an existing note with " · ")
  - `reconcile({ items, changes, signals, release, startup }) → { upserts: finding[] }` — the only place stage-changing
    automation lives: (a) promote eligible Signals with no item (`signalItemId` not present, any status); (b) item in
    Backlog whose Signal is `resolved` → `status:'fixed'`, `decisionNote:'Resolved on its own'`; (c) item whose
    `changeId` change is `applied` and status ≠ `fixed` → `status:'fixed'`, `shipped:{pending:true, at}`; (d) when
    `startup`, items with `shipped.pending` → `shipped:{version, commit, at, pending:false}` from `release`; (e) changes in
    `LIVE_CHANGE` with no item whose `changeId` matches → a new `source:'idea'` item, `status:'in_progress'`, title from
    `change.summary || change.request`.

  - `shouldPromote`: high/1 → true; medium/3 → true; medium/2 → false; resolved/high → false.
